Krystal Control Panel / Server card — “update available”

“Update available” — design directions

Twelve treatments for the same fact, drawn on a real .server-tile in the real palette. Option 0 is what ships today. Everything after it is a candidate. Pick a direction (or mix a head-row marker with a body treatment) and I’ll cut the rest.

What the design has to carry

  • It has a value, not just a flag. server.update_available is the target version string (2.0.55, or "new version available" when the engine reports no version). A bare icon throws that away.
  • It is only actionable when the server is stopped. verbGuard refuses Update on a running server (“Server must be stopped before updating”) — kgsm can’t rewrite files in use. So on an online card the state is information; on an offline card it is a call to action. Several options below are shown in both states.
  • Absence is three things, not one. Up to date, never checked (update_checked_at is null → “Checking for updates…”), and watchdog down. Only the first may render as silence.
  • The card is already dense. Art header, name, status pill, note line, five live metrics, three lifecycle buttons, a connect row — and it packs to a 280px column. Anything that adds permanent height loses; anything that only appears when an update is waiting can afford more.
  • Info-blue, not amber. An available update is a to-do, not a fault — the dashboard KPI already reads it as info tone. Amber/orange is reserved for in-transition states, and --update orange is the colour of the update running.

E · The state matrix any winner has to survive

Whichever direction wins, it has to answer all five of these — the card can’t claim a check nobody ran, and it can’t offer an action the engine will refuse.

Server stateWhat’s trueWhat the card should do
Offline + update update_available = "2.0.55", guard passes Full call to action. This is the only case where Update actually runs.
Online + update Guard blocks: “Server must be stopped before updating” State the update and the reason. Never render an Update control that just errors.
Updating now Status pill is already updating (amber, pulsing) The marker disappears — the pill owns the story. No two-colour double-report.
Never checked update_checked_at is null Silence on the card. “Checking for updates…” belongs on the detail page, not on a tile.
Watchdog down Status is unknown; every lifecycle verb is locked No update affordance at all — the panel can’t confirm anything about this server.
